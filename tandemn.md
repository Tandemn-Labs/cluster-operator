Tandemn is building software for orchestrating LLM inference workloads across different K8s clusters - e.g. a cluster in AWS us-east-1, a cluster in GCP us-east-1, a cluster on-prem etc. 

The central thing we are solving is: Given a changing set of inference jobs and their requirements as well as a potentially changing set of compute resources, how can we best place these jobs on the scattered, heterogeneous resources we have (clouds + on-prem + different accelerators). Jobs will primarily be online and batched inference workloads. The most important magic for us is the orchestration, our placement software, Koi, will examine job specifications, current resources and running metrics and make intelligent decisions like what GPU types to run on, which cluster to use, what parallelism configuration (TP/PP/DP/EP etc), what inference engine/serving framework etc. It creates an overall multi-cloud deployment plan that will encode the best placement of all jobs across all available resources. The orchestration does not merely make the placement once, it will track the jobs' metrics + progress and make changes dynamically to run them more optimally, such as moving individual jobs to different clusters, different instance types, different parallelism configs etc.

The goal is to design an entire framework that supports this planner. We can understand the planner as a black box component that accepts 3 inputs: (1) Jobs; (2) Live resource map (All resources + What is running on what); (3) Metrics from currently running jobs; and produces 1 output: (1) GlobalPlan. This planner will be a component in a Tandemn control plane. This control plane will have several components, including the planner (for us, it's Koi), a shared PostgreSQL database instance, a resource map service, a chunk manager service etc.

There will be a ClusterPlan CRD defined that will encode the deployment intent for each cluster. This CRD will contain information like GPU types, parallelism configuration, engine, network setup etc. On each individual K8s cluster, there will be a Tandemn operator that will interpret that CRD and translate it into the K8s objects as expected by that specific K8s cluster in that cloud environment.

The plan is to use existing frameworks for online jobs, like Nvidia Dynamo, llm-d, AiBrix and Ray Serve. For batched inference, we deploy vLLM ourselves with a batched driver that will bring in input chunks and write output chunks, interacting to and from object storage.
